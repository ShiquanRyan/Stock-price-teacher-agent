# 🤖 AI 股市領航員 (Stock Market Mentor Agent) 技術流程規範書

本專案實作一個基於 **Code-First (代碼主導)** 設計哲學的 AI 股市多代理人 (Multi-Agent) 導讀系統。系統能動態擷取即時金融數據、總體經濟指標與媒體輿情，並透過**「動態條件路由」**與**「雙軌事實查核」**機制，提供使用者深入淺出、且不被媒體噪音誤導的每日股市成因導讀。

本系統專為高併發試用情境設計，全面採用開源技術棧，並導入 Serverless 雲端架構與後端快取攔截機制，兼顧執行穩定度與 Token 成本控制，具備極高的高可用性（High Availability）與系統強健性（Robustness）。

## 🛠️ 一、 開源技術棧與環境組態 (Tech Stack & Setup)

本專案堅持「全開源生態系」原則，除基礎雲端運算與大語言模型 API 外，其餘組件皆採用開源且免費的解決方案。

### 1. 核心技術選型
* **Agent 核心框架**：`langgraph` (用於構建有向圖狀態機，精準控管資料流)
* **LLM 驅動（可自由替換）**：`langchain-google-genai` (Gemini API) 或 `langchain-openai` (OpenAI API)
* **後端 API 服務**：`fastapi` + `uvicorn` (異步高效能 Web 框架，支援高併發 Websocket / HTTP)
* **快取與記憶體資料庫**：`redis` (開源高可用記憶體資料庫)
* **數據與資料爬蟲**：`yfinance` (金融與財報數據)、`beautifulsoup4` + `requests` (輿情爬蟲)
* **前端互動介面**：`streamlit` (純 Python 響應式前端)

### 2. 本地開發環境配置
#### 步驟 A：複製本專案並建立虛擬環境
* 透過 Git 工具將遠端儲存庫複製至本地，並使用 Python 內建的 venv 模組建立隔離之虛擬環境，隨後依據作業系統類型啟動環境。

#### 步驟 B：安裝依賴套件
* 在專案根目錄下配置依賴宣告清單，包含自動化圖形狀態機套件、大模型整合介面套件、非同步網頁框架套件、記憶體資料庫驅動套件、金融與網絡爬蟲套件以及環境變數解析套件，並透過終端機執行封裝安裝。

#### 步驟 C：環境變數配置 (`.env`)
* 在專案根目錄下手動建立環境組態檔案，明確宣告包含大語言模型金鑰、外部快取資料庫存取端點、服務監聽連接埠以及生產環境識別標籤之配置項目。

## 📋 三、 端到端執行流程細節 (Execution Details)

### 步驟 1：前端用戶請求與快取攔截機制 (Cache-Aside Phase)
* **用戶輸入發起**：課堂上的多位使用者透過手機或網頁，輸入指定的股票代號（例如：2330.TW 或 NVDA），並發送分析請求。
* **快取檢索判斷**：網頁請求進入後端系統後，系統會率先根據當天日期與股票代號組合成一個唯一的識別鍵（Key），向開源記憶體資料庫發出同步查詢。
* **分流執行決策**：
  * **快取命中 (Cache Hit)**：若快取資料庫中已存在今日下午收盤後生成的分析報告，系統將不調用任何大模型或爬蟲工具，直接在毫秒級別內將數據結構回傳給前端網頁，實現高速回應並徹底消除 Token 開銷。
  * **快取未命中 (Cache Miss)**：若快取無資料，系統才會正式初始化後端的狀態機，並依序觸發下述的圖形節點流程。

### 步驟 2：常態環境與輿情數據擷取 (Data Ingestion Phase)
* **基礎金融硬數據擷取**：系統透過專屬金融工具包，即時向外部證券資料端點獲取當日股價 K 線、漲跌幅、成交量、以及核心指標（如 KD 線與 MACD 狀態）。同時，並行擷取大盤指數（如加權指數或費城半導體指數）與同行業競業股價，以利後續進行板塊輪動關聯分析。
* **總體經濟與替代指標獲取**：系統會同步擷取市場波動率指數（如 VIX 恐慌指數），作為量化當前地緣政治或宏觀環境恐慌程度的替代硬數據。
* **媒體輿情盲爬**：系統啟動非同步網絡請求，即時掃描並抓取當天主流財經媒體（如 Yahoo 財經、鉅亨網等）的前 20 篇相關新聞、市場評論以及社群討論文本。

### 步驟 3：事件驅動之動態條件路由 (Dynamic Routing Phase)
* **文本關鍵字掃描**：系統接收到常態輿情文字後，會利用高效能的正則表達式或輕量級語義分類模型，對所有新聞標題與摘要進行特定關鍵字（如：財報、法說會、業績展望等）的即時過濾。
* **分支路徑選擇**：
  * **深度驗證分支 (Trigger)**：若新聞文本中提及近期有重大公司財報發布或法說會召開，圖形的條件邊（Conditional Edge）將會動態切換，將狀態引導至「深度文件爬蟲節點」。系統將即時前往資料庫爬取官方的當季季報數據，或下載法說會語音轉文字的逐字稿摘要（Transcript）。
  * **常態直達分支 (Go Straight)**：若掃描後確認今日並非財報日或法說會，且無官方重大公告，系統將自動跳過深度文件爬蟲節點，直接匯流至智能體分析流程，藉此最大化減少不必要的雲端資源浪費與網絡延遲。

### 步驟 4：多智能體協作事實查核與思辨推理 (Multi-Agent Phase)
* 當所有必要的數據（第一手官方文檔或第二手媒體新聞）匯流至全局狀態後，系統將啟動三個獨立且相互依賴的大模型智能體（Agents）進行階層式推理：
* **新聞主編 Agent 執行去噪**：該智能體專職負責「非結構化數據的降維與去噪」。它會細讀所有盲爬的新聞，剔除重複的廣告文字、大盤通膨的無關長文，精確篩選出與該個股今日走勢最具直接物理關聯的 3 條核心焦點，並為每條焦點撰寫精簡摘要。
* **事實查核大師 Agent 執行雙軌交叉驗證**：此智能體負責防範媒體的「敘事偏見（Narrative Bias）」。它會將大盤與板塊數據、新聞主編摘要，與動態路由抓取到的官方第一手財報數據或法說會逐字稿進行多源對照。它會明確抓出媒體是否有刻意標題殺、散佈散戶恐慌、或是忽略了官方財測利多的落差事實。
* **財經小老師 Agent 執行最終導讀與風險預警**：作為最終決策節點，此智能體會將事實查核結果，轉化為深入淺出、具備思辨邏輯的白話文分析。同時，它會檢視外部財經日曆，列出未來一週或一個月內可能左右股價的事件催化劑（Catalysts）。
* **防禦性強健性控制 (Self-Awareness)**：若系統當前面臨的是天災或地緣政治等「缺乏官方第一手 Ground Truth 資料」的突發黑天鵝事件，財經小老師 Agent 被強迫必須降低其信心指數，並在結構化輸出中將噪音警告標籤設為開啟，藉此啟動前端的容錯黃色警示，防止 AI 產生幻覺瞎編。

### 步驟 5：狀態持久化、快取回寫與前端渲染 (Delivery Phase)
* **快取更新 (TTL 設定)**：LangGraph 狀態機執行完畢後，終端會輸出結構化且格式嚴格固定的 JSON 報告。FastAPI 後端在將結果回傳給該用戶之前，會同步將此 JSON 結構回寫入開源快取資料庫中，並根據交易收盤時效設定合適的存活時間（TTL，如 2 小時），以造福下一個查詢相同股票的用戶。
* **響應式前端渲染**：網頁端接收到結構清晰的 JSON 響應後，利用指標元件將今日漲跌幅、外資法人動向以鮮明的紅綠顏色呈現，並將 AI 主編的去噪新聞、事實查核對照表以及小老師導讀漂亮地渲染在用戶的手機或電腦畫面上。

## 🎯 四、 市場定位與核心差異化競爭力 (Market Positioning & UVP)

本系統與傳統金融機構、大眾財經媒體及坊間股市社群 App 有著本質上的降維打擊優勢：

### 1. 對抗「傳統網銀與券商 App」：從資訊堆疊走向思辨歸因
* **傳統金融盲點**：僅提供密密麻麻的數字、K線與技術指標，預設使用者具備專家解讀能力，且因嚴格金融法規包袱，網銀 App 傾向「少做少錯」，絕不主動為使用者進行漲跌因果解釋。
* **本專案核心優勢**：打破資訊不對稱，利用 Multi-Agent 在後端自動完成「數據與時事的因果歸因分析」，直接將生硬數值轉化為直覺、白話的邏輯導讀。

### 2. 對抗「股市爆料同學會與社群論壇」：群體盲從的理智濾網
* **社群平台痛點**：充斥散戶極端情緒、跟風踩踏、未經證實的造謠與主力故意釋放的韭菜誘餌，導致使用者極易陷入 FOMO 或 Panic Selling 恐慌。
* **本專案核心優勢**：系統作為高純度的「市場噪音過濾器」。當社群論壇集體盲從或恐慌時，**Fact-Checker Agent** 會立刻以硬數據與法說會逐字稿官方來源擊碎市場謠言，實現科學的數據交叉驗證。

### 3. 對抗「坊間投資教學與賣課 App」：動態時事因果 vs 滯後死板公式
* **現有軟體缺陷**：多流於「馬後炮式」的靜態公式套用（如本益比、KD指標固定買賣點），一旦遭遇天災、黑天鵝外生衝擊，公式集體失靈且完全無法解釋原因。
* **本專案核心優勢**：採用事件驅動的「動態事件歸因」，大腦會即時追蹤全球最新政經脈絡（如 Computex 發表會、美聯儲決議），且具備開源透明的「信任護城河（Trust Moat）」，無商業投顧抬轎之利益衝突。

## ☁️ 五、 雲端 Serverless 部署架構設計 (Cloud Infrastructure)

為了確保在 Live Demo 或真實高併發環境下，系統不會因為瞬間湧入的請求而卡死或翻車，專案採用雲原生（Cloud-Native）無伺服器架構進行橫向擴展優化。

### 1. 後端與狀態機 Docker 容器化
* 系統將 FastAPI 服務、LangGraph 狀態機邏輯、以及相關爬蟲組件，統一打包成一個輕量級的 Linux 容器映像檔（Docker Image），確保開發、測試與雲端生產環境的環境配置絕對一致。

### 2. Google Cloud Run 動態水平擴展
* 將編譯好的容器映像檔推送到 Google Artifact Registry 鏡像庫，並部署至 **Google Cloud Run**。
* 開啟「允許未經驗證的呼叫」，確保使用者無需繁瑣的登入流程即可透過手機直接調用後端。
* 配置 Serverless 的秒級自動擴展（Auto-scaling）機制。平時系統處於零容器運作狀態，維持零閒置成本；當 Live Demo 現場全班同學同時掃碼並發送大量查詢時，雲端平台會在 1 秒內自動並行加開數個容器實例，完美分攤並發流量，確保每位使用者都能獲得流暢、不卡頓的體驗。

### 3. 前端網頁託管與解耦
* 前端 Streamlit 應用程式與後端 API 進行徹底的解耦（Decoupling）。前端網頁被託管在專屬的雲端託管平台（如 Streamlit Community Cloud），僅透過一條公開的網址安全地與部署在 GCP Cloud Run 上的後端 API 進行異步數據交換。用戶端瀏覽器只需下載極輕量的前端網頁，核心運算與爬蟲負載全由雲端 Serverless 叢集吸收。
